## Описание проекта
Автоматизированное тестирование REST API учебного сервиса **Яндекс Самокат** (`https://qa-scooter.praktikum-services.ru/`)
API (`https://qa-scooter.praktikum-services.ru/docs/`)

### Покрытая функциональность:
1. **Создание курьера** (`POST /api/v1/courier`) - создание валидного курьера, проверка невозможности создания двух одинаковых курьеров и курьеров с существующим логином, проверка обязательных полей.
2. **Логин курьера** (`POST /api/v1/courier/login`) - авторизация существующего курьера с проверкой возврата `id`, проверка ошибок при неверном логине/пароле, авторизации несуществующего пользователя и отсутствии обязательных полей.
3. **Создание заказа** (`POST /api/v1/orders`) - параметризованные тесты выбора цвета самоката (`BLACK`, `GREY`, оба цвета, без указания цвета) с проверкой возврата `track`.
4. **Список заказов** (`GET /api/v1/orders`) - проверка получения непустого списка заказов в теле ответа.

## Архитектура проекта
* `data.py` - URL-адреса эндпоинтов и ожидаемые тексты ответов согласно документации API.
* `helpers.py` - метод регистрации курьера и генераторы тестовых данных с использованием `Faker`.
* `courier_methods.py` и `order_methods.py` - классы с HTTP-методами, размеченные шагами `@allure.step`.
* `conftest.py` - фикстуры подготовки тестовых данных и их гарантированного удаления/отмены после завершения тестов (`yield` teardown).
* `tests/` - тестовые классы, разделённые по проверяемым ручкам (без условий `if` и логики очистки внутри тестов).

## Обнаруженные баги API и расхождения с документацией (зафиксированы в Allure)
Тесты написаны строго по спецификации API, поэтому при прогоне фиксируют следующие дефекты стенда (`Product defects`):
1. **Создание дубликата курьера (`POST /api/v1/courier`)**: при коде ответа `409 Conflict` сервер возвращает сообщение `"Этот логин уже используется. Попробуйте другой."` вместо указанного в документации `"Этот логин уже используется"`.
2. **Авторизация курьера без ключа `password` (`POST /api/v1/courier/login`)**: при отправке JSON без поля `password` сервер зависает и возвращает `504 Gateway Time-out` вместо ожидаемой ошибки валидации `400 Bad Request` (`"Недостаточно данных для входа"`).
